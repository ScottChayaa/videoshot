# yt-space UI 原型 · 驗收手冊

> 對象：測試人員　｜　版本：mockup 原型（假資料）
> 環境：手機直式視窗（Pixel 7／寬約 375–412px）；另請至少開一次平板寬度與**深色模式**
> 開啟：專案根目錄執行 `pnpm mock`，再開 <http://localhost:8231/uiux-v2/login.html>
> （要先登入才進得去，直接開 home.html 會被導到登入頁；localStorage 的 key 一律 `ytspace2_`）
>
> 依據：2026-08-31 的 UI/UX 體檢報告；2026-09-01 的 v1 決定（Q-1～Q-11，已併入
> [現行規格](../../docs/superpowers/specs/2026-09-10-yt-space-app-design.md)）。

> **2026-09-10 更新說明**
> 產品改為 Android 原生 app（Kotlin ＋ Jetpack Compose，見現行規格）。以下條目已過期，會在 app 版實作計畫中改寫，在那之前以規格為準：
> §一「登入」整節（app 不需要登入，改為 Google Drive 備份與還原）、§四第二步的「手動補圖」（改為【截圖】）、
> §八的【登出】（改為中斷 Google 連結）、§九 關於 R2 與 sprite 簽章的描述（縮圖改存本機）。
> 其餘 UI 條目仍然有效。

> **2026-09-01 更新說明**
> v1 的認證改用 **Cloudflare Access ＋ Google IdP**（登入攔在 Cloudflare 邊緣，站內沒有登入頁），
> 另有五項版面決定沿用原型現況。受影響的條目已在下方增刪，第一節整節改寫。
> 標示 ⏳ 的是尚未確認的條目，驗收時先不計成敗。

## 零、先看整體（不必操作）

- [ ] **底部導覽有文字**：首頁／查詢／取圖／分類／**帳號**，五個項目都是圖示＋文字。
- [ ] **紅色只用在破壞性動作**：整個原型裡只有「刪除」是紅的，主要動作一律是主色。
- [ ] **間距與字級有尺標**：間距只用 4/8/12/16/24/32，字級只有 6 階。
- [ ] **深色模式**：把系統切成深色再走一遍，每一頁都要能讀。
- [ ] **鍵盤操作**：用 Tab 走一遍首頁，每個可點的東西都要看得到焦點框。
- [ ] **平板寬度**：600px 以上會加欄。（桌機版面 v1 不做，900px 以上不必驗）

## 一、登入（2026-09-01 整節改寫）

> **v1 沒有站內登入頁。** 認證由 Cloudflare Access 在邊緣完成：未登入者的請求根本到不了我們的
> 伺服器，而且因為只掛一個 IdP（Google）並開啟 instant authentication，連 Cloudflare 自己的
> 登入頁都會跳過 —— 開站就直接進 Google 的帳號選擇器。
>
> 因此原型的 `login.html`／`auth.js` **不會移植到正式版**，本節在原型上無從驗起。
> 下列條目屬於**階段 13 上線後**在 `shots.scottchayaa.com` 實機驗收。

- [ ] **未登入時開任何一頁都會被擋**：用無痕視窗直接貼深層網址（例如 `/folders`），
      應該立刻被導去 Google 登入。重點：**連 HTML 都不該送出來** ——
      攔截發生在 Cloudflare 邊緣，不是頁面畫完才擋。
- [ ] **開站直接看到 Google 帳號選擇器**：中間不該出現 Cloudflare 的登入頁或任何過場頁。
      （若出現，表示 instant authentication 沒開）
- [ ] **登入後回到原本要去的地方**：接上一條，登入完成後應該回到 `/folders`，不是首頁。
- [ ] **不在名單上的帳號會被擋**：用另一個 Google 帳號登入，應該看到阻擋頁而不是進得去。
- [ ] **已經登入就不會再被要求登入**：關掉分頁再開，應該直接進站。
- [ ] **帳號頁的資料來自登入狀態**：名稱／Email／頭像字母跟登入的帳號一致（不是寫死在 HTML 裡）。
      注意頭像是**姓名字母**不是 Google 大頭貼 —— Access 不提供照片。
- [ ] **登出**：帳號頁【登出】→ 確認 → 應該回到 Google 登入流程，
      且此時再按上一頁也回不去（走的是 `/cdn-cgi/access/logout`）。
- [ ] **session 過期不會讓畫面壞掉**：等 session 逾時後再操作任一功能，
      應該重新走一次登入然後回到原頁，**不該出現空白畫面或 JSON 解析錯誤**。
- [ ] **裝成 PWA 之後仍然正常**：把站加到主畫面、從主畫面開啟，登入轉跳
      **不該把使用者踢出應用視窗**。（這是 Access 特有的風險，見計畫 R-4）
- [ ] 深色模式下 Google 的登入頁本來就支援，不必另外驗。

> **這一節在原型上不必驗。** 原型仍保留 `login.html` 作為進入點與流程示意，
> 但它不是驗收標的，發現問題不必回報。

## 二、首頁

- [ ] **每個月份都是固定三欄**，不隨當月張數改變。
      （原「欄數會跟著當月張數變」已於 2026-09-01 取消 —— 需要每月總數，
      但既有的分頁設計拿不到，成本不划算）
- [ ] **卡片上只有縮圖，沒有描述文字**。
      （原「卡片上看得到描述」已於 2026-09-01 取消 —— 列表回傳不含 `description`）
- [ ] **預設沒有時間篩選**：一進來就是完整時間軸，不會有預設條件藏掉較新的資料。
- [ ] 右上角日曆鈕 → 選一個月份 → 出現**可清除的狀態列**「只顯示 ○年○月 以前的收藏 ✕」。
- [ ] ⏳ 月份標籤目前是**單行橫向捲動**（沿用原型現況）。
      原手冊要求「換行排列」，這一條**尚未確認**要不要改回來，驗收時先不計成敗。
- [ ] 縮圖是 `<button>`，可以用 Tab 選到、Enter 打開。

## 三、Lightbox

- [ ] **背景是不透明的**，底層的月份標題與縮圖不會透出來。
- [ ] 上方顯示「第 N / 共 M 張」。
- [ ] 第一次開啟會出現一次性的「左右滑動看上一張／下一張」提示。
- [ ] 動作**分層**：一顆主要【播放這一段】＋兩顆圖示鈕（加入分類／分享），
      【編輯圖資】【刪除這張收藏】收在右上 `⋯` 裡 —— 刪除不該跟瀏覽動作並排。

## 四、取圖

### 全流程
- [ ] **沒有底部導覽**，左上角是【✕】。三個步驟都一樣。
- [ ] 進度指示**有文字**：1. 貼網址 › 2. 挑畫面 › 3. 填資料。
- [ ] 動詞統一：【下一步】→【下一步】→【完成】。
- [ ] 第二／三步按【✕】→ 明確詢問「保留草稿並離開／捨棄草稿」，畫面上要說得出草稿還在不在。

### 第一步
- [ ] 歷史紀錄是**可點的清單列**（影片圖示＋標題＋日期＋張數），點了直接進第二步，
      不是只把網址填回輸入框。
- [ ] 亂打網址 → 錯誤訊息會說清楚該貼什麼格式。

### 第二步
- [ ] **一進來就已經收斂過**：頂部狀態列顯示「已收斂成 50 張候選，隱藏了 98 張相似畫面」，
      而不是打開就是 148 格的候選牆。
- [ ] 按【顯示全部】→ 148 張全出現，狀態列變成【重新過濾】，可以來回切。
- [ ] 收斂強度沿用「設定 › 取圖 › 過濾相似強度」（高／中／低）。
- [ ] **每格右上角有一顆 ▶**，點了跳到那一段；長按仍然有效，但不是唯一入口
      —— 鍵盤與輔助技術也要到得了。
- [ ] 工具列（全部選取／手動補圖／只看已選）**換行不截斷**，文字不會被切掉。
- [ ] 底部只有**一列**：「N 張候選 · 已選 k」＋【下一步（k 張）】，底下不再疊導覽列。
- [ ] 已收藏過的格子點下去會提示「這一格已經收藏過了」，不是靜靜地沒反應。

### 第三步
- [ ] 底部收成**同一塊 dock**（抽屜＋按鈕），不是抽屜／按鈕列／導覽列三層把縮圖區壓到剩四成。
- [ ] **主按鈕會變**：沒動過欄位時是【完成】；動了任一欄位就變成【套用到 N 張】。
      流程終點（【完成】）永遠是最搶眼的那一顆。
- [ ] 動過欄位時，按鈕上方出現「將更新：地點、標籤　其他欄位維持各張原值」
      —— 這條規則要看得見，不能只存在於腦袋裡。
- [ ] 分兩輪套用仍然正確：先勾 8 張填一組 → 再勾另外幾張填另一組 → 前一輪不受影響。
- [ ] ⏳ 時間欄位下方是中性說明「預設帶入 YouTube 的日期，可以改成實際拍攝日」，
      不是欄位標題旁邊的橘色 ⚠ 警告。
      **尚未確認**：規格第五節要求「來自上傳日時顯示 ⚠️ 提示、視覺上比其他欄位更顯眼」，
      兩者相反。驗收時先不計成敗。
- [ ] 【完成】→ 還有沒填的會提醒但不阻擋 → 回首頁、捲到該月份、toast「已新增 N 張」。

## 五、查詢

- [ ] **條件與結果在同一頁**：選完標籤按【查詢 N 個條件】→ 同頁換成結果，左上角出現返回鍵可以改條件，
      不會跳到另一個獨立頁面。
- [ ] 每個標籤 chip **帶張數**；選取後除了變色還會**多一個打勾**（不只靠顏色編碼）。
- [ ] 按鈕停用時，下方會說**為什麼**：「先選一個以上的標籤或地點」，不是只把按鈕變淡。
- [ ] 按鈕文字會跟著選取數量變：【查詢 3 個條件】。
- [ ] 結果列顯示「N 張 · 全部日期 · 條件 chips」。
- [ ] 從首頁的月份標籤點進來時，條件與時間會自動帶入並直接顯示結果。
- [ ] 動作列釘在導覽列上方，中間不會出現大段空白。

## 六、分類

- [ ] 每張資料夾卡片有**內容預覽拼貼**（最多 4 張）；空的資料夾顯示「還沒有圖片」。
- [ ] 卡片右下有一顆看得見的 `⋯`（改名／刪除）；長按仍然有效，但不是唯一入口。
- [ ] 沒有任何資料夾時，空狀態帶一顆【新增資料夾】，不是只有一句灰字。

## 七、詳細頁

- [ ] 播放器下方顯示**目前這一張的圖資**：描述、地點與標籤 chips、日期、影片秒數，
      以及一顆【編輯這張的圖資】—— 縮圖下方不該是大片空白。
- [ ] 收藏縮圖右上角有**編輯鈕**；點縮圖＝跳播放，長按＝編輯（仍保留）。

## 八、帳號（原「設定」）

> 2026-09-01：導覽列第五格與路由定名為**「帳號」**（`/account`），版面沿用原型現況。

- [ ] **保留漸層 hero ＋ 三格統計卡**。
      （原「沒有漸層 header 也沒有三格統計卡」已於 2026-09-01 取消）
- [ ] **三格統計的數字正確**：收藏片段＝總張數、本月新增＝以 `event_date` 落在本月的張數、
      來源影片＝去重後的影片數。三格都是可點的入口。
- [ ] **圖示對得上語意**：取圖＝漏斗、標籤管理＝標籤、AI 分析＝星芒、縮圖服務＝圖片。
      同一個圖示不會出現在兩個不同語意的地方。
- [ ] 【登出】移到最底、用破壞性樣式。
- [ ] 各細項頁的說明文字是**這個設定會影響什麼**，不是操作教學句。
- [ ] **設定值真的存得住**：改過「過濾相似強度」與「AI 分析區間」之後重新整理，
      值應該還在。（原型的 AI 秒數目前重整就回預設，正式版要修掉）
      注意這兩項只存在本機，**換一台裝置會回到預設值**，這是刻意的。

## 九、已知的取捨

- 「相似過濾」在 mock 裡是以**固定間隔**模擬（高＝每 5 張留 1、中＝每 3 張留 1、低＝每 2 張留 1），
  正式版才是畫面指紋（dHash）；這裡只是示意。
- 縮圖仍取自 YouTube storyboard sprite。**這裡有兩種不同的降級，要分開驗**：
  - **sprite 網址簽章過期（圖回 403）** → 退回該影片的封面圖，縮圖牆照樣有東西可看。
  - **整支影片解不出 storyboard spec**（影片太短／直播中／剛上傳，或解析器失效）
    → 縮圖牆是空的，只開放【手動補圖】，**不當機**。
- 正式版的首頁與查詢結果讀的是存進 R2 的單格 webp，**不受 sprite 簽章過期影響**；
  上面那條降級只發生在取圖第二步的候選牆。
- 詳細頁與分類頁在資料很少時仍會有下方留白 —— 這是資料量的結果，不是版面沒處理。
