# 非同步讀取寫回畫面狀態要注意什麼？

[← 回目錄](README.md)

- **規則**：非同步讀取回來要先算結果，再 `_state.update { it.copy(…) }`。**不要把 suspend 呼叫寫在 `.copy(…)` 的參數裡**

  ```kotlin
  // 錯：先取當下的舊狀態，再等網路，回來把整份舊快照寫回
  _state.value = _state.value.copy(player = watchPage())

  // 對：先等結果，再以最新狀態為底更新
  val player = watchPage()
  _state.update { it.copy(player = player) }
  ```

- **為什麼**：Kotlin 先求出 `_state.value`（舊快照）才去執行參數裡的 suspend 呼叫；等待期間別的讀取已經寫了新值（例如 `loading = false`），回來時整份舊快照會把它蓋掉
- **真實案例**：詳情頁永遠停在「正在載入…」。`DetailViewModel.loadPlayerInfo` 等 watch page 約 1 秒，回來把 `loading = true` 的舊快照寫回，蓋掉圖資讀取早就寫好的 `loading = false`（commit `4832d60`）
  - 同樣寫法另有五處一併修掉：詳情頁標籤、首頁／查詢頁月份選項、資料夾頁子資料夾、帳號頁回填進度
  - 首頁那處會讓晚到的月份把已載入的列表蓋回載入中
- 被取消的舊工作也不該寫回過期的值：換了目標就先取消舊的，或寫回前檢查還是不是同一個目標
