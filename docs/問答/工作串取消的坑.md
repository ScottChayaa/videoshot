# WorkManager 的工作串取消一支，有什麼坑？

[← 回目錄](README.md)

剪輯輸出「一次只跑一支、其餘排隊」的做法：每個任務一個工作，用 `enqueueUniqueWork(同一個名字, APPEND_OR_REPLACE, …)` 接在同一串後面。

- **取消串頭（正在跑的那支），後面排隊的會被連帶取消**。那些任務在資料庫還是「等待中」，要在取消**真的套用之後**（`cancelAllWorkByTag(...).await()`）把它們重新排回去；沒等到就補排，會讀到還沒取消的狀態而跳過。
- **不要取消排隊中的工作**：串的末端一旦是「已取消」（或「失敗」），下一次 `APPEND_OR_REPLACE` 會把**同名的整串都刪掉，包括正在跑的那支**，新工作立刻開始 → 兩支同時輸出、搶硬體編解碼器、共用同一個進度通知。
  排隊中的任務改成只刪資料列；它的工作輪到時讀不到任務，直接結束。
- 驗法（實機）：A 輸出中、B 排隊，取消 B，再導出 C → C 必須是「等待中」，通知欄同一時間只能有一條「輸出影片中」。
- 這個行為文件沒寫清楚，是反組譯 work-runtime 2.10.0 的 `EnqueueRunnable` 確認的；升級 WorkManager 後要重驗。
