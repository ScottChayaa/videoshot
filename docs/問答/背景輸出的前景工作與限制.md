# 剪輯在背景輸出，Android 會擋什麼？

[← 回目錄](README.md)

- **輸出用 WorkManager 的前景工作**（`setForeground`＋一條進度通知）。app 按 Home、鎖屏都照常跑；系統把它當前景服務，不會因為 app 在背景就停。
- **Android 12 起 app 在背景不能「新開」前景服務**。但排在同一串工作後面的下一支，在前一支結束時接著開始，實機（Android 12）不受這個限制：第一支跑時按 Home，第二支照樣在背景自己接著跑完。
- **app 被殺或手機重開後不會自己接著跑**：任務留在「輸出影片中」，下次打開 app（回到前景、開得了前景服務）時改回等待中、從頭重新輸出。小米等國產系統預設也不讓 app 開機自啟。
- **`am kill` 殺不掉正在跑前景服務的程序**（它只殺可以安全結束的背景程序）。要模擬「app 被殺」，用強制停止：

  ```bash
  adb shell am force-stop com.xenyaa.videoshot
  ```

  強制停止會連排好的背景工作一起清掉，比系統殺程序更嚴格；重開 app 後任務照樣要能從頭跑完。
- **收回相片權限時系統會直接殺掉 app 程序**，輸出被中斷；而且 Android 12 沒權限時 MediaStore **仍列得出 app 自己存進相簿的影片**，不能拿「素材清單是不是空的」判斷有沒有權限，要直接問系統。
- **前景服務類型**：Android 14 起一定要宣告；這裡 Android 15 起用 `mediaProcessing`、10～14 用 `dataSync`（manifest 兩個都宣告，程式依版本選）。上架時 Play Console 要申報用途。
- **背景比留在畫面上慢**：系統降低背景程序的優先權，輸出大約慢 1.4～1.6 倍；螢幕關著又更慢一些。所以導出畫面提示「留在這個畫面會比較快」。
