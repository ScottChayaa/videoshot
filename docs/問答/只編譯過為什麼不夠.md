# 為什麼只編譯過、單元測試綠燈還不夠？

[← 回目錄](README.md)

三個真實案例（都在階段 12），從此定下兩條規矩：**外部 SDK 呼叫與 androidTest 要上實機真的跑一次**、**大階段收尾前用乾淨的 `git worktree` 全新編譯重跑測試**。

## 1. Play Services 少一個欄位，編譯期完全看不出來

- 【中斷連結】第一次在實機按就失敗：`GisGoogleAuth.unlink()` 組 `RevokeAccessRequest` 時只呼叫 `.setAccount(account)` 就 `.build()`，少了 `.setScopes(...)`
- Play Services 內部對沒設定的 scopes 做 `.toArray()`，直接 NPE
- 語法合法、只是執行期缺必要欄位，只編譯驗證過、從沒真的呼叫過 Play Services 才會漏掉（commit `52032c8`）

## 2. 測試用的 OkHttp 會自己重試，把要測的路徑吃掉

- `DriveBackupStoreTest` 用 `SocketEffect.CloseSocket()` 模擬上傳中途斷線
- 真機的真實 TCP 下，OkHttp 預設的 `retryOnConnectionFailure` 會用新連線重送同一個請求，拿到乾淨回應——`DriveBackupStore` 自己的續傳邏輯根本沒被觸發
- 修法：**只在測試用的 `OkHttpClient` 關掉 `retryOnConnectionFailure`**；正式環境保留預設（合理的韌性行為）

## 3. incremental 編譯快取蓋住了壞掉的測試

- 某個任務改了共用介面，另外三個既有測試檔理論上該編譯失敗
- 本機 Gradle 的 incremental Kotlin 編譯沒有重新檢查那幾個檔案，好幾輪「測試全綠」都沒發現，直到下一個任務全新編譯才踩到
- 收尾前用乾淨的 worktree 重跑：

  ```bash
  git worktree add /tmp/vs-clean HEAD
  cd /tmp/vs-clean/android && ./gradlew :core:test :app:testDebugUnitTest :app:assembleRelease
  ```

  跑完 `git worktree remove /tmp/vs-clean`
