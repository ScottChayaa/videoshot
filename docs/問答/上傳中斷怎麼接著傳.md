# 上傳到 YouTube 中途被殺或斷網，怎麼從斷掉的地方接著傳？

[← 回目錄](README.md)

剪輯上傳用 YouTube Data API 的可續傳上傳（`videos.insert`、`uploadType=resumable`），程式在 `publish/ClipUploadRunner.kt`、`OkHttpYoutubeUploader.kt`。

- **工作階段網址一拿到就先存進任務**（`edit_task.upload_url`），再開始傳第一段。存之前被殺，最多重開一個工作階段；存之後被殺，下次就能接著傳。
- **接著傳之前先問 YouTube 收到幾個位元組**：對工作階段網址送空的 `PUT`，帶 `Content-Range: bytes */總長`。
  - 回 308：`Range: bytes=0-N` 表示收到 N+1 個位元組，從那裡接著傳（沒有 `Range` 就是 0）。只傳一半的那段 YouTube 可能只收了一部分，所以斷線後一律先問，不自己推算。
  - 回 200／201：**已經傳完了**，body 裡就有影片編號，直接拿來用、不再傳。這是「最後一段傳完、寫進資料庫之前被殺」的情況，YouTube 上不會多一支。
- **拿到影片編號先寫進任務、再刪 `out.mp4`**：順序反了，被殺在中間就是「成品沒了、任務還在上傳中」，只能重新輸出。
- **斷網在工作裡等**：註冊網路回呼，等「驗證過」的網路（`NET_CAPABILITY_VALIDATED`，要登入的 Wi-Fi 不算）最多 10 分鐘；等到了照退避接著傳。網路說回來卻一直連不上時也要計次退避，不然會空轉。
- **讀檔失敗不是斷網**：成品被刪或變短時也是 `IOException`，先比檔案長度，不對就直接失敗「輸出的影片不見了」，不要去等網路。
- **OkHttp 的同步呼叫不跟協程取消**：`call.execute()` 會一直卡到這段傳完。取消上傳時要自己 `call.cancel()`（在另一個監看取消的協程裡），並把取消造成的 `IOException` 換回 `CancellationException`。
- **取消的工作不刪網址與成品**：系統停掉的工作下次要接著傳；只有使用者取消時由呼叫端刪任務與 `edits/{taskId}/`。
- **使用者取消上傳會在 YouTube 工作室留下一支空殼**：影片在開工作階段時就建立了，取消後停在「即將開始處理」。`youtube.upload` 權限刪不掉它，所以確認框提醒使用者到工作室刪。
- 實機驗法：上傳中關 Wi-Fi 與行動數據 1 分鐘再開，百分比要停住不退回；上傳中強制停止再開 app，要從原本的百分比接著傳。

```bash
adb shell am force-stop com.xenyaa.videoshot
```
