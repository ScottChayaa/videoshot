# 階段 20：剪輯的輸出影片 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目標：** 編輯畫面按【導出】→ 確認抽屜 →【開始】後，草稿變成背景任務、進「導出中」畫面；用 WorkManager 前景工作在背景把時間軸輸出成 1080p mp4（app 縮小、鎖屏照跑，通知欄看得到進度，完成或失敗跳通知）。打勾「完成後自動上傳到 YouTube」的停在「輸出完成」（上傳是階段 21），沒打勾的存進手機相簿；成品可以全螢幕播放檢查。剪輯頁列出任務。

**架構：** 純規則（用到的素材、預設標題、空間估算）放 `:core/timeline`。任務存在 `cache.db` 新表 `edit_task`（v3→v4），只走 `CacheRepo`。新套件 `com.xenyaa.videoshot.edit` 放輸出相關：`ClipExporter`（Media3 Transformer，沿用預覽的 `clipComposition`、`MimeFirstExtractorsFactory`、`BlurBackgroundEffect`）、`ClipExportRunner`（一個任務從頭到尾的邏輯，全部依賴可換，JVM 測得到）、`ClipExportWorker`（WorkManager 前景工作的薄殼）、通知。存相簿走 `media` 模組新的 `MediaSaver`。畫面在 `ui/clip/`。

**技術：** Kotlin、Jetpack Compose、Room、WorkManager 2.10（已有）、Media3 1.10.1 Transformer／ExoPlayer（已有）、Robolectric、`am instrument`（實機）。

**規格：** [`../specs/2026-09-10-videoshot-app-design.md`](../specs/2026-09-10-videoshot-app-design.md) 第十九節「導出」「背景任務」（含背景輸出實驗、導出中畫面、要不要上傳）「資料」「架構」；路線圖[階段 20](2026-09-11-videoshot-android-實作計畫.md)；實驗程式在分支 `spike/stage20-bg-export`（`app/src/debug/.../debug/spike/SpikeExport.kt`，Transformer 與前景工作的寫法可以照抄，不合併）。

## 全域限制

- applicationId／Kotlin 套件：`com.xenyaa.videoshot`；minSdk 26、targetSdk 37。
- 模組邊界：本機相片與影片的讀取、**寫入相簿**只走 `media`；`edit_task` 只走 `CacheRepo`；Media3 只出現在 `ui/clip/ClipComposition.kt`、`Media3ClipPreview.kt`、`edit/Media3ClipExporter.kt`、`ui/clip/ClipResultScreen.kt`；純邏輯放 `:core/timeline`。
- 非同步讀取的結果先算好，再 `_state.update { it.copy(…) }`（AGENTS.md）。
- 規格寫死的值：輸出 H.264／AAC mp4、**1080p**（直式 1080×1920、橫式 1920×1080）、**30fps**（影片高於 30fps 才降，`FrameDropEffect`）；成品 `filesDir/edits/{taskId}/out.mp4`；開始前檢查空間，門檻**預估大小 × 2**，預估 **每分鐘 75_000_000 bytes**；一次只輸出一支、其餘排隊；被中斷就從頭重新輸出；沒打勾的存進相簿 `Movies/videoshot/`；勾選框預設打勾。
- 這個計畫自己定的值（規格沒寫，Claude 的決定）：
  - `edit_task.state` 存 `queued`／`rendering`／`rendered`／`failed`；存相簿的是 `rendered`＋`gallery_uri` 有值。
  - 勾選框只在「等待中、輸出中」顯示與可改；輸出完成後藏起來（階段 21 輸出完立刻接上傳，不會有可改的空檔）。
  - 前景服務類型：API 35 起 `mediaProcessing`，29～34 `dataSync`；通知頻道兩個：`clip_export_progress`（名稱「影片輸出進度」，`IMPORTANCE_LOW`）、`clip_export_result`（名稱「影片輸出結果」，`IMPORTANCE_HIGH`）。
  - 進度寫資料庫與更新通知：百分比有變才寫，最多每秒一次。
  - 相簿檔名：標題把 `/ \ : * ? " < > |` 換成 `-`，加 `.mp4`；Android 9 以下寫相簿要 `WRITE_EXTERNAL_STORAGE`（maxSdk 28），跟讀取權限一起要。
- 畫面文字（一字不差）：
  - **導出抽屜**：標題「導出」；摘要一行「0:48・直式・會成為 Shorts」／「1:20・橫式・一般影片」；超過上限時紅字「3:48・直式・超過上限 48 秒，請先刪掉一些段落」（差距一分鐘以上寫「1 分 12 秒」，整分寫「2 分」）且【開始】停用；欄位標籤「標題」；小字「以「非公開」上傳到你的 YouTube」；按鈕【開始】（標題空白也停用）。
  - **預設標題**：「videoshot 2026/10/20～10/27」；同一天「videoshot 2026/10/18」；跨年「videoshot 2025/12/30～2026/01/02」（`～` 是全形 U+FF5E）。
  - **導出中畫面**（頂欄「導出」＋返回）：等待中「等待中…」；輸出中「輸出影片中…」＋大字「42%」；提示「留在這個畫面會比較快；離開也會在背景繼續」；勾選框「完成後自動上傳到 YouTube」；【取消導出】→ 確認框標題「取消導出？」內文「已經輸出的部分會刪掉。」按鈕【取消導出】（破壞性）【繼續導出】。完成「影片輸出完成」＋「〈標題〉・0:48」＋【播放檢查】；存相簿「已存到相簿」＋同一行＋【播放】；失敗「影片輸出失敗」＋原因＋【重試】。
  - **剪輯頁任務列**：「等待中」「輸出影片中 42%」（＋細進度條）「輸出完成」（＋ ▶︎）「已存到相簿」（＋ ▶︎）紅字「失敗：〈原因〉」（＋【重試】）；長按選單：等待中／輸出中【取消】（同上確認框），完成／失敗【刪除任務】→ 確認框「刪除這個任務？」，`rendered` 且沒存相簿的加內文「app 裡輸出的影片會一起刪掉。」，按鈕【刪除】（破壞性）【取消】。
  - **建立任務失敗**（編輯畫面的 snackbar）：「導出失敗，請再試一次」。
  - **失敗原因**：「空間不足，還需要 1.2 GB」（不到 1 GB 寫「350 MB」，GB 取一位小數）、「素材都已不存在」、「讀不到相片和影片，請確認存取權」、「輸出失敗」。

## 審查重點

1. **輸出途中 app 被殺或手機重開**：任務不能永遠卡在「輸出影片中」。app 回到前景時把 `rendering` 改回 `queued` 重新排程；系統不讓背景開前景服務時，任務留在「等待中」。（Task 6 的測試）
2. **建任務與清草稿要一起成功或一起失敗**：寫任務失敗時草稿必須還在。（Task 2、Task 7 的測試）
3. **標題裡有「/」**：預設標題本來就有，存相簿的檔名不能因此失敗或變成子資料夾。（Task 3 的測試）
4. **輸出中取消或刪除任務**：任務不能被寫回來（復活），半成品要刪掉。（Task 5 的測試）
5. **輸出失敗或空間不足**：任務變「失敗」、說人話的原因、半成品刪掉、【重試】從頭再來；讀不到素材清單（整份空）時不能把素材全當成被刪。（Task 5 的測試）

### Task 5：一個任務的流程（`ClipExportRunner`）

**Files:**
- Create: `edit/ClipExportRunner.kt`、`edit/ExportTexts.kt`
- Test: `test/.../edit/ClipExportRunnerTest.kt`、`ExportTextsTest.kt`

**Interfaces:**
- Consumes: Task 1、2、3、4；`MediaLibrary`、`ClipDraft.pruneMissing`（階段 19）。
- Produces:
  - `ExportTexts.kt`：`fun formatBytes(bytes: Long): String`、`fun overLimitText(overMs: Long): String`（「48 秒」「1 分 12 秒」「2 分」）、`fun exportSummary(orientation: ClipOrientation, durationMs: Long): Pair<String, Boolean>`（文字、是否超過上限）、通知文字 `fun doneNotificationText(title: String, skipped: Int): String`；失敗原因常數 `REASON_ALL_MISSING`、`REASON_CANNOT_READ`、`REASON_EXPORT_FAILED`、`fun reasonNoSpace(missingBytes: Long)`。
  - `interface ClipExportNotifier { fun progress(task: EditTask, percent: Int); fun finished(task: EditTask) ; fun failed(task: EditTask, reason: String) }`
  - `class ClipExportRunner(repo: CacheRepo, library: MediaLibrary, exporter: ClipExporter, saver: MediaSaver, notifier: ClipExportNotifier, dirFor: (Long) -> File, freeBytes: () -> Long, now: () -> Long)`，`suspend fun run(taskId: Long)`：
    1. 讀任務；不存在、或不是 `queued`／`rendering` 就結束。
    2. `library.list(ALL)`；整份空但草稿有素材 → 失敗「讀不到相片和影片，請確認存取權」（不修剪）。否則 `pruneMissing`，時間軸空了 → 失敗「素材都已不存在」；記下略過幾個。
    3. 空間：`freeBytes() < requiredFreeBytes(時長)` → 失敗「空間不足，還需要 X」。
    4. `rendering` 0%，輸出到 `dirFor(id)/out.mp4`；進度有變才寫庫與通知。
    5. 成功後**重讀**任務：已被刪掉 → 刪檔結束。`autoUpload` → `setEditTaskRendered(id, skipped, null)`；否則 `saver.saveVideo`，成功就刪 app 裡的檔並寫 `galleryUri`，失敗 → 失敗「輸出失敗」。最後 `notifier.finished`。
    6. `ClipExportException` → 刪半成品、失敗「輸出失敗」、`notifier.failed`。取消（`CancellationException`）→ 刪半成品後往外丟。
