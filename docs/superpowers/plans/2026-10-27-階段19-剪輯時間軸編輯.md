# 階段 19：剪輯的時間軸編輯 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目標：** 選完素材按【下一步】進到真正的編輯畫面：上半部預覽（方向不同的素材置中＋模糊背景），下半部時間軸（播放頭固定中間、拖時間軸移動），可以分割、刪除、復原、重做；所有改動存成草稿，離開或 app 被殺掉都能從剪輯頁「編輯中」那一列續做。

**架構：** 時間軸的資料與操作（段落、分割、刪除、復原重做、草稿 JSON、素材消失時的修剪）全部是 `:core/timeline` 的純邏輯，JVM 測得到。草稿存在 `cache.db` 新的 `edit_draft` 表（v2→v3）。預覽用 Media3 的 `CompositionPlayer`：`ui/clip/ClipComposition.kt` 把時間軸轉成 `Composition`（影片段用剪輯區間、照片段用圖片長度，方向不同時加 `Presentation` 拉伸＋`GaussianBlurWithFrameOverlaid`）。編輯畫面只透過 `ClipPreview` 介面碰播放器，Robolectric 測試換假的。

**技術：** Kotlin、Jetpack Compose、kotlinx.serialization（`:core` 已有）、Room（`cache.db`）、**Media3 1.10.1**（`media3-transformer`、`media3-effect`、`media3-common`、`media3-ui-compose`；新依賴）、Robolectric、`am instrument`（實機）。

**規格：** [`../specs/2026-09-10-videoshot-app-design.md`](../specs/2026-09-10-videoshot-app-design.md) 第十九節「編輯畫面」「資料」「架構」「入口與剪輯頁」（草稿那幾條）；路線圖[階段 19](2026-09-11-videoshot-android-實作計畫.md)；[已知缺口](../../已知缺口.md)裡三條「剪輯選素材」（載入時一片空白、修剪要用全部清單比對、被殺後選取遺失）在這個階段解決。

## 全域限制

- applicationId／Kotlin 套件：`com.xenyaa.videoshot`；minSdk 26。
- **本機相片與影片的讀取只走 `media` 模組**（`MediaLibrary`、`MediaThumbLoader`）；`edit_draft` 只走 `CacheRepo`；Media3 只出現在 `ui/clip/ClipComposition.kt` 與 `ui/clip/Media3ClipPreview.kt`。
- **純邏輯放 `:core/timeline`**（不依賴 Android），JVM 單元測試覆蓋；時間一律毫秒 `Long`。
- 非同步讀取的結果先算好，再 `_state.update { it.copy(…) }`（AGENTS.md）。
- 規格寫死的值：照片段 **3000 ms**；復原與重做紀錄**各最多 50 步**；直式上限 **180_000 ms**、橫式 **600_000 ms**（`ClipOrientation.maxDurationMs`，階段 18 已有）；輸出尺寸直式 **1080×1920**、橫式 **1920×1080**；素材**由舊到新**排列。
- 這個計畫自己定的值（規格沒寫，都是 Claude 的決定）：時間軸比例 **1 秒＝40dp**；分割後每一段至少 **100 ms**（離段落邊界不到 100 ms 時【分割】停用）；模糊 `sigma = 30f`；預覽用 `SurfaceView`。
- 畫面文字（一字不差）：
  - 編輯畫面頂欄標題「編輯」，右上【導出】；總長度顯示在標題下一行「總長 1:48」，超過上限時變紅色並接「（超過 3 分鐘上限）」或「（超過 10 分鐘上限）」
  - 播放列：「0:12 / 1:48」（`m:ss`，一小時以上 `h:mm:ss`，同 `formatDuration`）；圖示鈕 TalkBack 名稱「播放」「暫停」「復原」「重做」

  - 空時間軸：「時間軸是空的」＋副標「按 ↶ 復原可以找回剛刪掉的段落」

  - 【導出】這個階段還沒有功能，按了顯示提示「導出在下一個階段加入」（階段 20 換掉）

## 審查重點

1. **續做時沒有權限，不能把整條時間軸當成「素材都不見了」清空。** 權限被撤銷或沒授權時 `MediaLibrary.list` 回空清單；編輯畫面要先判權限，不是 FULL／PARTIAL 就顯示權限提示、不修剪草稿。（Task 5 的「沒權限續做不修剪」測試）
2. **在段落邊界或極短處分割。** 播放頭剛好在兩段交界、或離邊界不到 100 ms 時【分割】停用；不會產生 0 長度或負長度的段落。（Task 1）
3. **刪到空再復原。** 刪光所有段落後【導出】停用、顯示空時間軸；復原要能一路回到最初，重做要能一路回去；做新操作後重做清空。（Task 1、Task 5）
4. **草稿 JSON 壞掉或是舊格式。** 解不開就當成沒有草稿（不當機、剪輯頁不顯示「編輯中」），並把壞掉的那列清掉。（Task 2、Task 3）
5. **影片段的剪輯區間與預覽時間對不上。** 分割後第二段的預覽要從原片的分割點開始，不是從原片開頭；跨段播放時進度連續。（Task 4 的對應測試＋Task 9 實機）

**Interfaces:**

    - `val durationMs: Long`
    - `fun locate(positionMs: Long): Pair<Int, Long>?`——回傳（段落索引, 段內偏移）；`positionMs` 落在兩段交界時屬於**後一段**（偏移 0）；超出範圍回 null（`positionMs == durationMs` 也回 null）。
    - `fun startOf(index: Int): Long`
    - `fun canSplitAt(positionMs: Long): Boolean`——段內偏移與段尾距離都 ≥ `MIN_SEGMENT_MS`（100）才 true。
    - `fun splitAt(positionMs: Long): Timeline?`——不能分割回 null。
    - `fun delete(index: Int): Timeline`
  - `const val PHOTO_SEGMENT_MS = 3000L`、`const val MIN_SEGMENT_MS = 100L`
  - `fun initialTimeline(sources: List<ClipSource>): Timeline`——依 `takenAtMs` 由舊到新（同時間依 `id` 由小到大），照片 3000 ms、影片 `0..durationMs`；`durationMs` 為 null 或 ≤ 0 的影片略過。
  - `data class EditHistory(val current: Timeline, val undo: List<Timeline> = emptyList(), val redo: List<Timeline> = emptyList())`，成員 `fun apply(next: Timeline): EditHistory`（current 推進 undo、重做清空、undo 超過 `MAX_HISTORY`＝50 丟最舊的）、`fun undo(): EditHistory?`、`fun redo(): EditHistory?`（沒得做回 null）、`val canUndo`、`val canRedo`。
