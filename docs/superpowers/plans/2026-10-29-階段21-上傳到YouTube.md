# 階段 21：剪輯上傳到 YouTube 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目標：** 打勾「完成後自動上傳到 YouTube」的任務，輸出完接著以「非公開」上傳到使用者自己的 YouTube 頻道（可續傳：斷線、app 重開都從斷掉的位元組接著傳），上傳成功刪掉 `out.mp4`，再用 `youtube` 模組輪詢 watch page 直到有 storyboard 才算「已完成」；導覽列【剪輯】掛已完成的紅點數字；失敗說人話、【重試】從失敗的那一步開始。

**架構：** 純規則（標題清洗、錯誤分類、輪詢間隔）放 `:core/publish`。任務表 `edit_task` 以 migration（cache.db v4→v5）加 `failed_step`、`upload_url`、`video_id`，狀態多 `uploading`／`processing`／`done`。新套件 `com.xenyaa.videoshot.publish`（規格邊界 7：**YouTube Data API 只在這裡用**）：`YoutubeUploader`（OkHttp 打 REST，薄）、`ClipUploadRunner`（一個任務的上傳流程，依賴全可換、JVM 可測）、`StoryboardPoller`＋`StoryboardPollWorker`、`UploadAuthFlow`（連結＋增量授權的步驟）。`youtube.upload` 的授權仍只在 `backup` 的 `GoogleAuth` 拿。

**工作串的取捨（決定：上傳跟輸出排在同一串、同一個工作裡，等 storyboard 另外排）：**
- 每個任務仍是 `clip-export` 串上的一個 `ClipExportWorker`（`APPEND_OR_REPLACE`、排隊中的任務取消時不取消工作，照階段 20），工作裡依序跑「輸出 → 上傳」，上傳完（進入 YouTube 處理中）才結束、串才輪到下一支——正好是規格「前一個上傳完才開始下一個的輸出」。
- 不把上傳拆成另一串的理由：(1) 另一串的第一個工作在 app 縮小時開不了前景服務（Android 12 起的限制；同一串接力才不受限，見問答「背景輸出的前景工作與限制」），上傳會卡到下次開 app；(2) 輸出完要「插隊」到上傳串，`APPEND_OR_REPLACE` 只能接在串尾，排序與取消會再踩一次「整串被換掉」的坑；(3) 同時兩條前景通知。代價：A 上傳時 B 不能先輸出（總時間較長），規格本來就這樣要求，接受。
- 等 storyboard 不佔串：每個任務一串 `clip-storyboard-{taskId}`，不是前景工作、要求有網路，每次查完把下一次接在自己後面（`APPEND_OR_REPLACE` 接在執行中的自己後面＝等這次成功才跑）；可以好幾個任務同時等。

**技術：** Kotlin、Compose、Room、WorkManager 2.10（已有）、OkHttp 5.5（已有）、Google Identity Services `AuthorizationClient`（已有）、`mockwebserver3`（JVM 測試要新加 `testImplementation`）、Robolectric、`am instrument`（實機）。

**規格：** [`../specs/2026-09-10-videoshot-app-design.md`](../specs/2026-09-10-videoshot-app-design.md) 第十九節「導出」「背景任務」（上傳、等 storyboard、失敗原因、一次只跑一個任務）「Google 授權與 YouTube 權限」「資料」「架構」；第十節「Google 帳號與 Drive 權限」；路線圖[階段 21](2026-09-11-videoshot-android-實作計畫.md)；階段 20 的[計畫](2026-10-28-階段20-剪輯輸出影片.md)與[開發紀錄](../../開發紀錄/階段20-剪輯輸出影片.md)；問答[背景輸出的前景工作與限制](../../問答/背景輸出的前景工作與限制.md)、[工作串取消的坑](../../問答/工作串取消的坑.md)。

## 全域限制

- 路徑簡寫：`app/…` ＝ `android/app/src/main/java/com/xenyaa/videoshot/…`，`test/…` ＝ `android/app/src/test/java/com/xenyaa/videoshot/…`，`androidTest/…` 同理，`core/…` ＝ `android/core/src/main/kotlin/com/xenyaa/videoshot/core/…`。
- applicationId／套件 `com.xenyaa.videoshot`；minSdk 28（Android 9）、targetSdk 37。
- 模組邊界：YouTube Data API（`www.googleapis.com/upload/youtube/v3`）只出現在 `publish/`；watch page 只走 `youtube` 模組的 `Youtube.watchPage`；Google 授權 API（`Identity`、`AuthorizationRequest`）只在 `backup/`；`edit_task` 只走 `CacheRepo`。
- 非同步讀取的結果先算好，再 `_state.update { it.copy(…) }`（AGENTS.md）。
- 規格寫死的值：公開狀態固定 `unlisted`、說明欄留空；`videos.insert` 可續傳（`uploadType=resumable`），上傳網址存進任務；拿到 `videoId` 後**立刻刪 `out.mp4`**；storyboard **前 5 分鐘每 30 秒、之後每 2 分鐘、最多 60 分鐘**，逾時失敗「YouTube 還沒產生縮圖」、【重試】只重新等不重傳；帳號沒頻道（`youtubeSignupRequired`）「這個 Google 帳號還沒有 YouTube 頻道」；連結時只拿 `drive.appdata`，第一次導出才另外要 `youtube.upload`；用帳號頁連結的同一個 Google 帳號；紅點只算「已完成」，1～9、超過 9 寫「9+」；失敗不算紅點。
- 這個計畫自己定的值（Claude 的決定，可推翻）：
  - `edit_task.state` 多 `uploading`／`processing`／`done`；`failed_step` 存 `render`／`upload`／`storyboard`。
  - 上傳分段 **8 MiB**（`8L * 1024 * 1024`，YouTube 要求 256 KiB 的倍數）；斷網時在工作裡等網路回來，**最多等 10 分鐘**，等不到就失敗「沒有網路連線」（重試從斷掉的位元組接著傳）；不限 Wi-Fi。
  - 伺服器暫時錯誤（5xx、408、429）退避 1、2、4、8、16 秒重試 5 次；存取權杖 401 重拿一次權杖再試；上傳網址失效（404、410）清掉網址、從 0 開新的工作階段一次。
  - 中繼資料：`snippet.title`＝清洗後的標題、`snippet.description`＝""、`snippet.categoryId`＝"22"、`status.privacyStatus`＝"unlisted"、`status.selfDeclaredMadeForKids`＝false。
  - 標題清洗：`<`→`＜`、`>`→`＞`（YouTube 不收角括號），去頭尾空白，超過 100 個字（code point）截斷，空的用「videoshot」。
  - 前景服務類型：有要上傳的任務在 API 35 起用 `mediaProcessing|dataSync`，29～34 `dataSync`（manifest 已宣告兩個，不用改）。
  - 等 storyboard 的計時從進入 `processing` 那一刻的 `updated_at` 起算；**`processing` 期間不寫 `updated_at`**。
  - 授權的時機：【開始】時（勾選框預設打勾）先走授權；使用者取消授權**照樣建任務但不打勾**，snackbar「沒有取得 YouTube 授權，這支不會上傳」。在導出中畫面把勾選框打勾、以及上傳那一步失敗後按【重試】，都先走一次授權（已授權時靜默通過）。
  - 階段 20 留下的「輸出完成、沒存相簿」任務（`rendered`＋`gallery_uri` 是 null）不自動上傳，維持原樣（可以播放、刪除）。
  - 已完成的任務點進去只顯示完成畫面與「開始取圖在下一個階段加入」（接取圖精靈是階段 22）。

## 審查重點

1. **上傳途中 app 被殺、系統不讓開前景服務、或斷網**：從存著的上傳網址查已收到的位元組接著傳，**不能重新輸出、不能從 0 重傳**；`uploading` 的任務在恢復與「前景服務開不了」時不可被改回 `queued`。（Task 2、Task 5、Task 7 的測試）
2. **最後一段傳完、寫 `video_id` 之前被殺**：重開後查詢工作階段拿到影片資源就直接進處理中，YouTube 上不能多一支。（Task 4、Task 5 的測試）
3. **標題有 `<`、`>`、超過 100 字或全是空白**：YouTube 不收這種標題，不能因此上傳失敗。（Task 1 的測試）
4. **上傳中或處理中取消／刪除任務**：任務不會被寫回來、`out.mp4` 刪掉、輪詢工作收掉、`clip-export` 串不被整串換掉（排隊中的仍只刪資料列）。（Task 5、Task 6、Task 9 的測試）
5. **授權被撤銷、帳號沒有頻道、額度用完**：說人話的原因、`failed_step=upload`；【重試】先走授權再接著傳，不重新輸出。（Task 4、Task 5、Task 8 的測試）
