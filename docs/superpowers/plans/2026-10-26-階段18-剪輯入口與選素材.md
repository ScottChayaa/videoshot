# 階段 18：剪輯的入口與選素材 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目標：** 底部導覽多一格【剪輯】；剪輯頁可以【新增剪輯】→ 選直式或橫式 → 在「全部／影片／照片」三個分頁裡依拍攝時間多選手機的照片與影片。選完按【下一步】先到「編輯（階段 19）」的佔位畫面。

**架構：** 新的 `media` 模組讀 MediaStore（列素材、取縮圖），是本機相片影片唯一的入口（規格第十九節「架構」的邊界 6；刪除在階段 22 才加）。畫面放在 `ui/clip/`：剪輯頁（`Tab.CLIP` 的根）、選方向抽屜、選素材畫面（`Dest.ClipPicker`，全螢幕、沒有底部導覽）、編輯佔位（`Dest.ClipEditor`）。選取狀態只在 `ClipPickerViewModel` 的記憶體裡——草稿是階段 19 的事。權限判斷寫成純函式，JVM 測得到。

**技術：** Kotlin、Jetpack Compose（BOM 與 material3 沿用專案現有版本）、MediaStore（`ContentResolver.query`、API 29 起 `loadThumbnail`）、`ActivityResultContracts.RequestMultiplePermissions`、Robolectric（Compose UI 測試跑在 JVM）、`am instrument`（實機）。不新增任何第三方依賴。

**規格：** [`../specs/2026-09-10-videoshot-app-design.md`](../specs/2026-09-10-videoshot-app-design.md) 第十九節「入口與剪輯頁」「選方向」「選素材」「架構」；路線圖[階段 18](2026-09-11-videoshot-android-實作計畫.md)。

## 全域限制

- applicationId／Kotlin 套件：`com.xenyaa.videoshot`；minSdk 26、targetSdk 37。
- **本機相片與影片的讀取只走 `media` 模組**（`com.xenyaa.videoshot.media`）；畫面與 ViewModel 只碰 `MediaLibrary` 介面與 `MediaThumbLoader`，不直接碰 `ContentResolver`。
- **不用 Android 內建的相片挑選器**（規格附錄 A-13：它給的 URI 不能刪除）。
- 純邏輯（權限判定、排序、拍攝時間的退回規則、選取順序）不依賴 Android 型別，JVM 單元測試覆蓋。
- 非同步讀取的結果先算好，再 `_state.update { it.copy(…) }`；不要把 suspend 呼叫寫在 `.copy(…)` 的參數裡（AGENTS.md）。
- 畫面一律用 `ui/common/` 的共用元件（規格第三節「UI 元件層」）；底部抽屜一律 `VsBottomSheet`；觸控區最小 44dp、可互動元件有 `focusRing()` 與 TalkBack 名稱。
- **同一個圖示不在兩個語意不同的地方出現**：`VsIcons.Film` 已經代表「來源影片」，剪輯格用新的 `VsIcons.Clapperboard`。
- 畫面文字（一字不差）：
  - 導覽格：「剪輯」
  - 剪輯頁標題：「剪輯」；空狀態：「把手機裡的照片和影片剪成一支片」，副標「上傳到你的 YouTube（非公開）後，就能用取圖精靈挑畫面」，按鈕【新增剪輯】

## 審查重點

規格沒明說、但最可能咬到使用者的情況（各自的測試已放進負責的 Task）：

1. **相簿很大（上萬張）**：打開「全部」分頁不能卡住畫面——查詢在 `Dispatchers.IO`、排序不在主執行緒、格線用 `LazyVerticalGrid` 加 `key`，縮圖按需載入且有 LRU。（Task 3 的排序測試用 20,000 筆；Task 5 的 ViewModel 測試確認讀取不在主執行緒以外的地方阻塞。）
2. **拍攝時間缺漏**：截圖、下載的圖、某些 app 存的影片沒有 `DATE_TAKEN`——要退回 `DATE_MODIFIED`，不能排到 1970 年最底下。（Task 3）
3. **使用者在設定裡改權限後回來**：從【前往設定】回到 app、或背景時被撤銷權限，畫面要在回到前景時重新判定，不是停在舊狀態或當機。（Task 6 的 `ON_RESUME` 重查測試）
4. **切分頁不丟選取**：在「全部」選了 3 個、切到「照片」再選 2 個，回到「全部」時 5 個都還勾著、序號照選取先後。（Task 4）
5. **舊版存下來的導覽狀態**：更新前存的 `NavCodec` 字串沒有 `CLIP` 那一格，不能因此整個重設成預設（使用者會發現分頁跳回照片）——缺的格子補成根畫面。（Task 1）

### Task 3：`media` 模組——素材、排序、權限判定

**Files:**
- Create: `android/app/src/main/java/com/xenyaa/videoshot/media/MediaItem.kt`
- Create: `android/app/src/main/java/com/xenyaa/videoshot/media/MediaSort.kt`
- Create: `android/app/src/main/java/com/xenyaa/videoshot/media/MediaAccess.kt`
- Test: `android/app/src/test/java/com/xenyaa/videoshot/media/MediaSortTest.kt`、`MediaAccessTest.kt`

**Interfaces:**
- Produces:
  - `enum class MediaKind { PHOTO, VIDEO }`
  - `enum class MediaFilter { ALL, VIDEO, PHOTO }`
  - `data class MediaItem(val id: Long, val uri: String, val kind: MediaKind, val takenAtMs: Long, val durationMs: Long?, val width: Int, val height: Int, val rotation: Int)`——`uri` 存字串（`content://…`），純 JVM 測試不需要 `android.net.Uri`；`id` 是 MediaStore 的 `_ID`（照片與影片同在 `files` 表，不會撞號）；`durationMs` 照片是 null。
  - `fun takenAtOf(dateTakenMs: Long?, dateModifiedSec: Long): Long`——`dateTakenMs` 為 null 或 ≤ 0 時用 `dateModifiedSec * 1000`。
  - `fun sortNewestFirst(items: List<MediaItem>): List<MediaItem>`——依 `takenAtMs` 由新到舊，同時間再依 `id` 由大到小（穩定、可預期）。
  - `enum class MediaAccess { FULL, PARTIAL, DENIED }`
  - `fun mediaAccessOf(sdkInt: Int, granted: Set<String>): MediaAccess`
  - `fun mediaPermissionsFor(sdkInt: Int): List<String>`——33 以下 `[READ_EXTERNAL_STORAGE]`；33 `[READ_MEDIA_IMAGES, READ_MEDIA_VIDEO]`；34 起再加 `READ_MEDIA_VISUAL_USER_SELECTED`。權限名稱用字串常數（`"android.permission.READ_MEDIA_IMAGES"` 等），不引用 `Manifest`，純 JVM 可測。

`mediaAccessOf` 的判定（Android 官方「部分存取」的寫法）：

```
sdk ≥ 34 且 READ_MEDIA_VISUAL_USER_SELECTED 有（上一條不成立） → PARTIAL
sdk ≥ 33 其他                                                  → DENIED
sdk ≤ 32：READ_EXTERNAL_STORAGE 有 → FULL，否則 DENIED
```
