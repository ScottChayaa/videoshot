# 階段 15D：查詢、分類、帳號對齊原型 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 查詢（條件與結果）、分類清單、帳號頁與其子畫面的外觀換成原型 `tags.html`／`folders.html`／`account.html`／`setting.html` 的樣子（改用階段 15A 的共用元件），收掉 15A～15C 最終審查指名「15D 採用前要修」的元件細節，最後做階段 15 的收尾：設計文件的有效結論併入規格與驗收手冊。

**Architecture:** 只動畫面層與共用元件；不改資料表、不加新的 SQL（查詢頁的標籤種類沿用 15C 已經加好的 `MonthFacet.tagKind`）。新增一組「設定頁」共用元件（分組、說明、單選列、步進器、下拉欄位），帳號子畫面一律用它們。`AppShell` 的內容區改成「消耗掉 Scaffold 已經給的 inset」，讓查詢頁的 `VsActionDock` 不會把系統導覽列高度墊兩次。

**Tech Stack:** Kotlin、Jetpack Compose、Robolectric（`:app:testDebugUnitTest`）、`pnpm compare`。

**Spec:** 設計文件（階段 15 收尾時已併入[現行規格](../specs/2026-09-10-videoshot-app-design.md)第三節「UI 元件層」與第六節「UI 與原型的差異」，原檔刪除、留在 git 歷史）（其第七節＝計畫 D；決定 5 正方形、決定 8 查詢兩種模式互斥、決定 10 不做查詢紀錄、決定 11 不做色系選擇器）；視覺來源 `mockups/uiux-v2/styles.css`（「查詢頁」「通用狀態」「分類」「設定／清單列」段落）與 `tags.html`／`folders.html`／`account.html`／`setting.html`；行為依據規格第六、九、十節與驗收手冊 §一、§五、§六、§八。

## Global Constraints

- 外觀照原型、行為照驗收手冊與規格（設計文件決定 1）。**原型與手冊不一致時以手冊為準**（CLAUDE.md）。**不改任何流程**：查詢條件／結果切換、facet 勾選與「顯示更多」、月份選擇、文字查詢的規則式／Gemini 解析與「聽懂了」、結果分頁、首頁月份標籤帶入條件；分類的搜尋、排序、新增／改名／刪除；帳號頁統計入口、各子畫面的設定存取、備份／還原／中斷連結、回填進度與按鈕、標籤管理（改名即合併、改 kind、別名、刪除只解關聯）、首次開啟選擇。
- **不做**：查詢紀錄與「沿用上次查詢」（決定 10）、主題色系選擇器（決定 11）。原型帳號頁的【登出】不做（app 沒有登入）。
- **紅色只用在破壞性動作**（手冊 §零）：中斷連結、刪除資料夾、刪除標籤、刪除這些收藏。錯誤／提示訊息用 `textDim` 或 `warn`。
- 間距只用 4／8／12／16／24／32（例外：查詢結果縮圖格線 2dp，同首頁）；字級 13／15／17／20／24／28；字重 Regular／Medium／Bold；圓角 8／12／全圓。
- 觸控目標最小 44dp；每個可點的東西都有 `focusRing()` 與 TalkBack 名稱；切換型的東西才帶選取狀態（`VsTagChip`／`VsToolbarPill` 的 `isToggle`）。
- 不寫死色碼（hero 漸層上的白字與半透明白用 `OnDarkColors`；圖上疊字用 `scrim`）。
- **非同步狀態更新慣例**：先算好結果再 `_state.update { it.copy(…) }`，不要把 suspend 呼叫寫在 `.copy(…)` 參數裡。
- 既有測試不得刪除或弱化；因文字或結構改變而調整的測試，最小幅度修改並註解原因。**TalkBack 名稱是行為**：既有的名稱不改，除非本計畫明寫。
- commit message 用繁體中文 `類型(範圍): 描述`，**不加 AI 生成標記**。
- 環境：`export JAVA_HOME=/snap/android-studio/current/jbr ANDROID_HOME=$HOME/Android/Sdk; export PATH=$PATH:$ANDROID_HOME/platform-tools`；Gradle 在 `android/` 下跑。
- 實機 10 分鐘無操作會上鎖：主控在背景跑保持喚醒腳本；截圖前確認 `isKeyguardShowing=false`，上鎖就停下來回報。

**Interfaces:**
- Produces:
  - `VsUnderlineTabs(…)`：每個分頁最小寬 44dp；外層 `Row` 加 `Modifier.selectableGroup()`
  - `VsEmptyState(message, modifier, icon = null, secondary: String? = null, actionText = null, onAction = null, actionVariant: ButtonVariant = ButtonVariant.Primary)`——`secondary` 是訊息下方 15 `textDim` 置中的第二行；`actionText` 與 `onAction` 必須同時給或同時不給（`require`）
  - `VsListRow(…)`：KDoc 寫明「`trailing` 若是可互動元件（Switch、按鈕），整列不要給 `onClick`，否則語意合併會吃掉它」；新增參數 `mergeSemantics: Boolean = true`，`false` 時不合併
  - `@Composable fun VsSettingGroup(modifier: Modifier = Modifier, title: String? = null, divided: Boolean = true, content: @Composable ColumnScope.() -> Unit)`——原型 `.set-group`：`surface` 底、上下各 1dp `border`、下距 24；`title` 13 Medium `textDim`、內距 12/16/4；`divided` 時子列之間 1dp `border` 分隔線（用 `ColumnScope` 讓呼叫端逐列放 `VsListRow`／`VsRadioRow`，分隔線由群組負責：實作上提供 `VsSettingDivider()` 給呼叫端在列之間放，或用 `Layout` 自動插——擇一，簡單為先）
  - `@Composable fun VsSettingNote(text: String, modifier: Modifier = Modifier)`——原型 `.set-note`：15 `textDim`、內距 0/16/16
  - `@Composable fun VsRadioRow(title: String, selected: Boolean, onSelect: () -> Unit, modifier: Modifier = Modifier, subtitle: String? = null)`——原型 `.set-row.pick`：整列可點、`Role.RadioButton`、`selected` 語意、右側 22dp 圓形選取記號（主色）
  - `@Composable fun VsStepper(value: Int, onChange: (Int) -> Unit, range: IntRange, modifier: Modifier = Modifier, label: String)`——原型 `.stepper`：−／＋ 兩顆 44×44 `surface2` 底 1dp `border` 圓角 8、字 20 `accent`；中間數值最小寬 48、Bold、等寬數字；到邊界時對應鈕停用；TalkBack：−「減少 {label}」、＋「增加 {label}」，數值節點唸「{label} {value}」
  - `@Composable fun VsSelectField(label: String, value: String, onClick: () -> Unit, modifier: Modifier = Modifier)`——原型查詢頁的時間欄位：標籤在上（15 Medium `textDim`，間距 8）、欄位 `surface` 底 1dp `borderStrong` 圓角 8 內距 12、值 17、右側 `VsIcons.ChevronDown`（若沒有就補，原型 `ICONS.chevronDown` `m6 9 6 6 6-6`）；整個欄位 `Role.Button`、名稱「{label}：{value}」
  - `VsTextField(…, leadingIcon: ImageVector? = null)`
  - `AppShell`：內容 `Box` 加 `Modifier.consumeWindowInsets(padding)`

**AppShell inset**：Scaffold 會把系統列 inset 換成 `padding` 給內容，但**不會標記成已消耗**；內容裡的 `VsActionDock` 再呼叫 `navigationBarsPadding()` 就會墊兩次（15A 最終審查 Minor 2）。改成 `Box(Modifier.fillMaxSize().padding(padding).consumeWindowInsets(padding))`。**改之前先 grep** 所有在 AppShell 內容裡呼叫 `navigationBarsPadding`／`imePadding`／`statusBarsPadding` 的畫面（目前已知 `RestoreScreen` 在 Scaffold 外、`LightboxScreen`／`BatchEditScreen` 在 Scaffold 外——確認它們真的都不在 AppShell 的 content 裡），報告裡列出檢查結果。
