# 相簿封存 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目標：** 相簿太多時，使用者可以把不常看的相簿封存起來；在相簿畫面下拉、過門檻後放手，進入「封存相簿」畫面。

**架構：** 封存狀態存在 `library.db` 的 `folder.archived_at`（v2→v3，`ADD COLUMN`），跟著備份走。repo 回傳的卡片帶 `archivedAt`，畫面端的 `FoldersStore` 把卡片拆成「沒封存」與「已封存」兩份，兩個畫面共用 `FoldersViewModel`。下拉手勢用 Material3 的 `Modifier.pullToRefresh`，跟 `PullToRefreshBox` 是同一套元件；1.4.0 版的 `PullToRefreshBox` 沒有 `enabled` 參數，搜尋時要能關掉下拉，所以直接用 modifier。轉圈的指示圖換成自己畫的「封存圖示＋文字」膠囊。

**技術：** Kotlin、Jetpack Compose（BOM 2026.02.01，material3 1.4.0）、Room（KSP，`room.schemaLocation` 匯出 schema）、Robolectric（Compose UI 測試跑在 JVM）、`am instrument`（實機儀器測試）。

**規格：** [`docs/superpowers/specs/2026-09-10-videoshot-app-design.md`](../specs/2026-09-10-videoshot-app-design.md)，第四節 `folder` 表與「schema 版本」、第六節「相簿」規則表（封存的五列）、第十三節整合測試第 30 條。

## 全域限制

- applicationId／Kotlin 套件：`com.xenyaa.videoshot`。
- 所有 DB 存取只走 repo（`LibraryRepo`／`RoomLibraryRepo`）。畫面與 ViewModel 不碰 DAO。
- `library.db` 的 schema 是跨平台資料契約：`LIBRARY_SCHEMA_VERSION` 是唯一的版本來源，`LIBRARY_MIGRATIONS` 必須涵蓋 1 到現行版本的每一階（`MigrationTest` 盯著）。
- v2→v3 只做 `ALTER TABLE folder ADD COLUMN archived_at INTEGER`，不重建任何表。
- 只有根層相簿（`parent_id IS NULL`）能封存；子相簿跟著上層一起隱藏。
- 畫面文字（一字不差）：
  - 選單項：【封存相簿】【取消封存】
  - 下拉提示：「下拉進入封存相簿」「放開進入封存相簿」
  - 封存相簿畫面標題：「封存相簿」
  - 封存相簿畫面空狀態：「還沒有封存的相簿」＋說明「在相簿的 ⋯ 選單選【封存相簿】」
  - 封存後的提示：「已封存「名稱」」「已取消封存「名稱」」
  - 失敗時的提示：「封存失敗，請再試一次」「取消封存失敗，請再試一次」
- 非同步讀取的結果，先算好再寫回 state，不要把 suspend 呼叫寫在 `.copy(…)` 的參數裡（AGENTS.md 慣例）。

```kotlin
package com.xenyaa.videoshot.data

import androidx.test.ext.junit.runners.AndroidJUnit4
import com.xenyaa.videoshot.data.library.LibraryDatabase
import com.xenyaa.videoshot.data.repo.LibraryRepo
import com.xenyaa.videoshot.data.repo.RoomLibraryRepo
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.test.runTest
import org.junit.After
import org.junit.Assert.assertEquals
import org.junit.Assert.assertFalse
import org.junit.Assert.assertNotNull
import org.junit.Assert.assertNull
import org.junit.Assert.assertThrows
import org.junit.Assert.assertTrue
import org.junit.Before
import org.junit.Test
import org.junit.runner.RunWith

/** 相簿封存（規格第六節「封存相簿」）：寫 `folder.archived_at`，只有根層能封存。 */
@RunWith(AndroidJUnit4::class)
class FolderArchiveTest {

    private lateinit var db: LibraryDatabase
    private lateinit var repo: LibraryRepo

    @Before fun setUp() {
        db = inMemoryLibraryDb()
        repo = RoomLibraryRepo(db, Dispatchers.IO)
    }

    @After fun tearDown() { db.close() }

    @Test
    fun 新建的相簿沒有封存() = runTest {
        repo.createFolder(null, "旅行")
        assertNull(repo.folderCards(null).single().archivedAt)
    }

    @Test
    fun 封存後卡片帶封存時間_取消封存後變回null() = runTest {
        val id = repo.createFolder(null, "旅行")

        repo.setFolderArchived(id, true)
        assertNotNull(repo.folderCards(null).single().archivedAt)

        repo.setFolderArchived(id, false)
        assertNull(repo.folderCards(null).single().archivedAt)
    }

    @Test
    fun 封存的相簿仍然列在根層卡片裡_由畫面自己分() = runTest {
        val a = repo.createFolder(null, "旅行")
        repo.createFolder(null, "貓")
        repo.setFolderArchived(a, true)

        assertEquals(listOf("旅行", "貓"), repo.folderCards(null).map { it.name }.sorted())
    }

    @Test
    fun 子相簿不能封存() = runTest {
        val parent = repo.createFolder(null, "旅行")
        val child = repo.createFolder(parent, "宜蘭")
        assertThrows(IllegalArgumentException::class.java) {
            kotlinx.coroutines.runBlocking { repo.setFolderArchived(child, true) }
        }
    }

    @Test
    fun 找不到的相簿不能封存() = runTest {
        assertThrows(IllegalArgumentException::class.java) {
            kotlinx.coroutines.runBlocking { repo.setFolderArchived(999, true) }
        }
    }

    @Test
    fun 樹上的子相簿跟著根層一起是封存的() = runTest {
        val parent = repo.createFolder(null, "旅行")
        repo.createFolder(parent, "宜蘭")
        repo.createFolder(null, "貓")
        repo.setFolderArchived(parent, true)

        val tree = repo.folderTree().associateBy { it.name }
        assertTrue(tree.getValue("旅行").archived)
        assertTrue(tree.getValue("宜蘭").archived)
        assertFalse(tree.getValue("貓").archived)
    }

    @Test
    fun 封存的相簿照樣開得起來() = runTest {
        val id = repo.createFolder(null, "旅行")
        repo.setFolderArchived(id, true)

        val node = repo.folderNode(id)
        assertEquals("旅行", node?.name)
        assertTrue(node!!.archived)
    }
}
```

(1) `tree()` 與 `nodeById()` 兩個 CTE 都多帶一欄 `archived`（根層看自己的 `archived_at`，子層繼承上層）：

```kotlin
@Query(
    """
    WITH RECURSIVE walk(id, parent_id, name, depth, archived) AS (
        SELECT id, parent_id, name, 1, archived_at IS NOT NULL FROM folder WHERE parent_id IS NULL
        UNION ALL
        SELECT f.id, f.parent_id, f.name, w.depth + 1, w.archived
        FROM folder f JOIN walk w ON f.parent_id = w.id
    )
    SELECT id, parent_id, name, depth, archived FROM walk
    """
)
suspend fun tree(): List<FolderNodeProjection>

@Query(
    """
    WITH RECURSIVE walk(id, parent_id, name, depth, archived) AS (
        SELECT id, parent_id, name, 1, archived_at IS NOT NULL FROM folder WHERE parent_id IS NULL
        UNION ALL
        SELECT f.id, f.parent_id, f.name, w.depth + 1, w.archived
        FROM folder f JOIN walk w ON f.parent_id = w.id
    )
    SELECT id, parent_id, name, depth, archived FROM walk WHERE id = :id
```

```kotlin
/** 相簿畫面看得到的（沒封存的）。不排序、不篩選——「N 個相簿」用它的張數。 */
fun active(state: FoldersState): List<FolderCard> = state.cards.filter { it.archivedAt == null }

/** 封存相簿畫面的清單：封存時間新到舊（規格第六節），同時間時 id 大的在前，順序才穩定。 */
fun archived(state: FoldersState): List<FolderCard> =
    state.cards.filter { it.archivedAt != null }
        .sortedWith(compareByDescending<FolderCard> { it.archivedAt }.thenByDescending { it.id })

/** 封存相簿畫面的空狀態。理由同 [emptyKind]：讀取中與讀取失敗都不算「真的沒有」。 */
fun archivedEmpty(state: FoldersState): Boolean =
    !state.loading && state.error == null && archived(state).isEmpty()
```

```kotlin
private val _notices = MutableSharedFlow<String>(extraBufferCapacity = 4)

/** 封存／取消封存的結果提示，`AppRoot` 收來顯示 snackbar（同一個 VM 服務兩個畫面）。 */
val notices: SharedFlow<String> = _notices.asSharedFlow()

fun archive(card: FolderCard) = setArchived(card, archived = true)

fun unarchive(card: FolderCard) = setArchived(card, archived = false)

/**
 * 寫完重查：卡片會從目前的畫面消失、出現在另一個畫面（兩邊都讀同一份 `cards`）。
 * 失敗只發提示，不寫進 `error`——那是「清單讀不到」的錯誤列，這裡清單本身沒問題。
 */
private fun setArchived(card: FolderCard, archived: Boolean) {
    viewModelScope.launch {
        try {
            repo.setFolderArchived(card.id, archived)
            reload()
            _notices.emit(if (archived) "已封存「${card.name}」" else "已取消封存「${card.name}」")
        } catch (e: CancellationException) {
            throw e
        } catch (e: Throwable) {
            _notices.emit(if (archived) "封存失敗，請再試一次" else "取消封存失敗，請再試一次")
        }
    }
}
```

```kotlin
/**
 * 取代 `PullToRefreshBox` 預設的轉圈：膠囊（封存圖示＋文字）跟著手指往下移，
 * 到門檻時剛好完整露出、圖示與文字變主色。沒在拉的時候整個不畫。
 *
 * 放手後不顯示轉圈：呼叫端的 `isRefreshing` 永遠是 false，`onRefresh` 直接換頁。
 */
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun ArchivePullIndicator(state: PullToRefreshState, modifier: Modifier = Modifier) {
    val fraction = state.distanceFraction
    if (fraction <= 0f) return
    val ready = fraction >= 1f
    val tint = if (ready) AppTheme.colors.accent else AppTheme.colors.textDim
    Row(
        modifier
```
