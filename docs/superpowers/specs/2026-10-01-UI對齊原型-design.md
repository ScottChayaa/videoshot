## 一、為什麼要做

2026-10-01 在 2107113SG（392dp 寬、淺色模式）上把每一頁跟原型並排比對，差距很大。

**根本原因不是個別畫面沒照做，而是少了「共用元件層」。** 色彩、間距、字級三套尺標已經從原型翻成
`ui/theme/`，但原型 `styles.css` 裡約 1,300 行的元件樣式（頂欄、標籤小膠囊、清單卡片、步驟條、
底部動作列、工具列小按鈕……）從來沒有翻過來。`ui/common/` 目前只有一個檔案，各畫面直接用
Material 的預設元件（58 個純文字按鈕、13 個外框輸入欄），所以整個 app 看起來是「Material 預設風」。

只逐頁修而不先建共用元件，同一種元件會在各頁各寫一次，之後又會各自走樣。

## 三、計畫與順序

```
計畫 A（共用元件層＋驗收工具）
   ├─→ 計畫 B（取圖精靈三步）
   ├─→ 計畫 C（首頁、Lightbox、詳情、資料夾內容）  ← 另外依賴「詳情頁永遠卡在正在載入」修好
   └─→ 計畫 D（查詢、分類、帳號）
```

A 做完之後 B、C、D 互不依賴。預設順序 **B → C → D**：B 落差最大、而且有違反手冊 §零的地方；
C 要等詳情頁的載入問題（已另開任務）先修好；D 以樣式差異為主。

## 四、計畫 A：共用元件層與驗收工具

### 共用元件（放 `ui/common/`，畫面只用這些）

| 元件 | 原型出處（`styles.css` 段落） | 規則 |
|---|---|---|
| 頂欄 | 頂部列 | 固定高度（原型 61px＝44 觸控鈕＋上下 8＋1 底線）、底部分隔線；左返回／關閉、標題、右側圖示鈕。有沒有按鈕都同高 |
| 底部導覽 | 底部導覽 | 五格圖示＋文字；「取圖」是實心主色圓角方塊；第五格依決定 4 |
| 標籤小膠囊 | chip、`app.js` 的 `KIND` | 帶種類圖示與種類色（地點 #0EA5E9、人物 #6366F1、主題 #8B5CF6、動物 #F59E0B、其他 #64748B，深淺模式同值（原型深色模式沒有覆寫））；選取時多一個 ✓；可帶張數 |
| 按鈕 | 按鈕（單一基底＋變體） | 主要／次要／純文字／破壞性四種；紅色只給破壞性 |
| 清單列、卡片列 | 設定／清單列 | 圖示＋主標＋副標＋ › |
| 底部動作列 | 取圖精靈、查詢頁 | 滿版主按鈕，左側可放狀態文字；自動避開系統導覽列與鍵盤 |
| 步驟指示 | 取圖精靈 | 三段進度條＋「1. 貼網址 › 2. 挑畫面 › 3. 填資料」 |
| 底線分頁、工具列小按鈕、可關閉提示卡、空狀態 | 查詢頁、通用狀態 | — |

種類色、頂欄高度等原型有、`ui/theme/` 還沒有的數值，補進 `ui/theme/`，不寫死在元件裡。
計畫 A 另外做一個**只在開發測試版看得到的元件總覽頁**，逐一列出每個元件的各種狀態（含深色模式），
當作元件驗收與之後的視覺參考。

### 驗收工具

**假資料匯入（只在開發測試版）**
- 資料來源：原型 `mock-data.js` 的 13 張收藏、12 支影片、標籤、資料夾。轉成 JSON 放在開發測試版專用的
  資源目錄，正式版完全不含這段程式與資料。
- 轉換規則：`kind='place'` 的標籤轉成 `shot.place`（取第一個）；其餘標籤照 kind 對應到 app 的四種；
  `start` 轉成 `at_sec`；依 `SB_SPECS` 算出 storyboard 層級與格子編號，形成縮圖識別碼。
- 縮圖不打包：匯入後交給既有的回填機制從 YouTube 抓（原型裡的 sprite 簽章已過期無妨，回填本來就重抓 watch page）。
  這同時是一次回填的實機演練。
- 觸發方式：電腦端指令（例如 `adb shell am broadcast`）。**會取代**實機上現有的圖庫。

**對照截圖腳本**
- 一行指令產出「原型｜實機」並排圖：原型用無頭 Chrome（開發機已裝）以 392×850、淺色模式截圖，
  實機用 `adb exec-out screencap`；兩邊各自的操作步驟（點開 Lightbox、進取圖第二步等）寫在腳本設定裡。
- 每個計畫收尾都附這張圖當驗收證據。

### 計畫 A 的驗收

匯入假資料後，每一頁的頂欄與底部導覽跟原型一致（對照圖）；元件總覽頁的每個元件在淺色／深色模式都對得上原型。

## 八、偏離清單（刻意不照原型做的地方）

| 地方 | 原型 | app | 理由 |
|---|---|---|---|
| 登入頁、【登出】 | 有 | 沒有 | app 不需要登入（規格、手冊 §一） |
| 導覽列第五格文字 | 設定 | 帳號 | 正式詞彙（CLAUDE.md 詞彙表） |
| 導覽列第五格圖示 | 永遠頭像 | 未連結人像、連結後頭像 | 沒連結時沒有字母可顯示（決定 4） |
| Lightbox 圖資區與頂欄日期 | 有 | 沒有 | 決定 7 |
| 查詢標籤小膠囊的張數 | 沒有 | 有 | 手冊 §五 |
| 查詢「沿用上次查詢」「查詢紀錄」 | 有 | 沒有 | 決定 10 |
| 帳號頁選單列 | 4 列 | 6 列（備份、縮圖、取圖、查詢、AI 分析、標籤管理） | 手冊 §八、階段 11～13 |
| 取圖第二步的播放器 | 自繪、有時間疊字 | YouTube 內嵌播放器 | 規格第五節（截圖必須走內嵌播放器），疊字不做 |
| 第三步每列張數 | 3 | 4 | 規格第五節第三步線框明定 4（規格＞原型） |
| 取圖紀錄日期 | `08/20 · 取了 4 張` | `2026-08-20 · 取了 4 張` | 不省略年份，跨年的紀錄才分得出來 |
| 手動格的時間標籤前綴 | 「手動 」 | 「截圖 」 | 正式詞彙是【截圖】（CLAUDE.md 詞彙表、手冊 §四） |
| 第三步欄位標題 | 「時間（事件發生日）」 | 「時間」 | 沿用既有標籤與測試定位用的語意名稱；說明文字已在欄位下方 |
| 截圖失敗提示的顏色 | 原型無此畫面 | `warn` 系列 | 不是破壞性動作，不用紅色（手冊 §零） |
| 第一步錯誤訊息的顏色 | `.wz-err` 用 danger | `warn` 系列 | 同上 |
| 進度條可往後跳 | 只有已完成的步驟可點 | 已到達過的步驟（含後面）都可點 | 沿用既有行為（`WizardViewModel.jumpTo` 與 `furthest`），不改流程 |
| 第三步抽屜高度 | 固定 | 設上限，鍵盤出現時縮到欄位與按鈕仍看得見 | 實機驗收：原型的固定高度在手機上會讓鍵盤蓋住聚焦中的欄位 |
| 工具列小按鈕的選取語意 | 無 | 只有切換型（【只看已選】）才宣告「已選／未選」，【全部選取】【截圖】不宣告 | 動作型按鈕讀成「未選取」會誤導 TalkBack（`VsToolbarPill.isToggle`） |
| 「已收藏」格子的提示 | toast | 對話框（「知道了」） | 沿用既有行為（`AlertDialog`），文字與原型相同 |

各計畫實作時若再發現原型與手冊不一致，補進這張表，不靜默決定。
