[← 回索引](README.md)

- **狀態**：完成並實機驗收
- **計畫**：[`2026-09-28-階段13-縮圖回填.md`](../superpowers/plans/2026-09-28-階段13-縮圖回填.md)
- **做法**：subagent-driven-development，12 個任務，再跑全分支最終審查（opus）＋一輪修正

## 做了什麼

- `BackfillManager`：掃描缺圖 → 依 `(videoId, sbLevel)` 分組抓 watch page → `SheetHarvester` 下載裁切 → 狀態機轉 `ok`／`missing`（退避）／`lost`
- `BackfillWorker`：WorkManager 一次性作業鏈、自我接續；`DelegatingWorkerFactory` 跟每日備份 worker 共存
- `BackfillScanWorker`：沒有任何網路約束的純本機掃描，開機時獨立排程（實機驗收時補的，見教訓）
- `FetchResult.RATE_LIMITED`（HTTP 429），回填層跟 `PARSE_FAILED` 一樣「整批暫停」
- `SheetHarvester.harvestRelocated`：storyboard 層級消失時用 `at_sec` 在新層級重新定位，圖仍寫回原識別碼
- `FileThumbs` 分辨「還在等回填」與「已確定 lost」（lost 顯示中性預留圖）
- 帳號頁「縮圖」子畫面：回填進度、【稍後重試】【刪除這些收藏】【用行動網路繼續】

## 驗收

- JVM **799 個**（`:core:test` 170 ＋ `:app:testDebugUnitTest` 629）全綠，用乾淨 `git worktree` 重編譯驗證過。
- **儀器測試 `OK (210 tests)`**（2107113SG，2026-09-30），本階段新增的方法都真的跑過。
- **實機走過 WorkManager 排程路徑**：純行動網路時 `dumpsys jobscheduler` 看到回填工作排進去但 `Ready: false`；切到 Wi-Fi 後真的執行，對假造的 `seed001` 打 watch page、分類成 `VIDEO_UNAVAILABLE`、5 張轉 `lost`；【稍後重試】立即重跑；【刪除這些收藏】後不用重開 app，帳號頁統計與首頁就同步更新。

## 教訓

- **全分支最終審查抓到 1 個 Critical＋6 個 Important**，都是組裝後才顯形的整合問題，已修：
  1. （Critical）目標檔案已存在的格子 `SheetHarvester` 不回報，該格永遠卡在 missing，`BackfillWorker` 無限自我重排 → 先用 `thumbs.exists()` 直接標 ok，收尾再補「沒回報的一律當失敗」
  2. 「同一支影片一律同一個 sbLevel」的假設會被兩次取圖之間 YouTube 換 spec 打破 → 依 `(videoId, sbLevel)` 分組，watch page 仍每支只抓一次
  3. 【稍後重試】只重設 DB 沒排工作 → 同時呼叫 `scheduleBackfill()`
  4. 手冊要求的【用行動網路繼續】接線都做了、畫面上沒有按鈕 → 補上
  5. 進度文字的顯示條件恆為真、永久掛在畫面上 → 改成 `total > done`
  6. 【刪除這些收藏】刪完不通知其他畫面重查 → 補上（查詢頁只在結果畫面才重查）
  7. 跨層級重新定位的座標換算沒有測試覆蓋 → 補回歸測試
- **實機才發現的缺口**：`scanForMissing()` 原本只在受 Wi-Fi 約束的 worker 裡跑，純行動網路時帳號頁完全不知道有缺圖、【用行動網路繼續】也不會出現。單元測試直接呼叫 `runBatch()`，測不到 WorkManager 的網路約束。修法是新增沒有約束的 `BackfillScanWorker`，已在純行動網路下重驗。
- **擱置三項**（Minor）見[已知缺口](../已知缺口.md)。
